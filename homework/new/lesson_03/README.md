## 1. ЗАДАНИЕ

### Цель

Научиться строить PromQL-запросы для измерения latency (p95, p99) с помощью `histogram_quantile`, рассчитывать процент ошибок (Error Rate), избегать антипаттернов агрегации (double aggregation, отсутствие группировки по `le`).

---

### Контекст / Легенда

Вы - инженер в e-commerce платформе. Сервис `checkout-service` отвечает за оформление корзины. Во время распродажи пользователи начали жаловаться на то, что кнопка «Оплатить» зависает, а затем выдает ошибку.

Дежурный разработчик посмотрел на базовый график и заявил: «Средний отклик системы 150 мс, всё летает!».

Причина ложных выводов разработчика - неправильные PromQL-запросы и попытка считать `avg()` поверх сырых гистограмм. Вам поручено написать корректные PromQL-запросы для Grafana и исправить метрики сервиса.

---

### Задача

1. Развернуть тестовый стенд с помощью `docker compose up -d`.
2. Изучить работу `checkout-service` под нагрузкой `k6`.
3. Найти проблему в `main.go`, где для некоторых запросов некорректно проставляются лейблы статусов и некорректно заполняются бакеты гистограммы.
4. Написать корректные PromQL-запросы:
    * **RPS по эндпоинтам:** Кол-во запросов в секунду на каждую ручку сервиса
    * **Error Rate (% ошибок 5xx):** Отношение сбойных запросов к общему числу.
    * **p95,p99 Latency:** Расчет 95-го, 99-го перцентиля latency с группировкой по `le`.
   Используйте подготовленный пример дашборда, который нужно поправить - [Grafana](http://localhost:3000/dashboards)
5. Проверить корректность работы с помощью авто-теста `check.sh`.

### Подсказки / Notes

После внесения изменений в `main.go` пересоберите и перезапустите контейнер приложения:

* **Квантили в PromQL:** Функция `histogram_quantile(0.99, scalar_expression)` требует, чтобы выражение внутри `scalar_expression` обязательно сохраняло лейбл `le`.


* **Частая ошибка (Антипаттерн):** Написание `sum(rate(...))` без `by (le)` удаляет лейбл бакетов `le`, из-за чего `histogram_quantile` не работает правильно.


* **Пропорция ошибок (Error Rate):**
Считается как отношение запросов с ошибками к общему числу запросов.
