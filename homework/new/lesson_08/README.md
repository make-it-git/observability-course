# Домашняя работа: Observability & SRE Error Budget Alerting

## Тема
Практическое применение Error Budgets и Multi-Burn Rate Alerting.

---

## 1. Задание

### Цель
Научиться диагностировать критическое сгорание бюджетов ошибок (Error Budget Burn Rate) и рассчитывать метрики с помощью PromQL в Prometheus.

### Контекст / Легенда
Вы работаете SRE-инженером. После ночного деплоя сервиса `order-service` дежурный инженер получил критический алерт: **Burn Rate превысил 14.4** (сжигание более 2% бюджета ошибок за 1 час). Клиентские запросы завершаются со статусом `500 Internal Server Error`, а задержка ответа сервиса выросла.

Согласно регламенту компании:
* **SLO сервиса:** 99.9% успешных запросов.
* **Error Budget:** 1 - SLO = 0.1%.

### Задача

В каталоге project

1. Развернуть инфраструктуру командой:
   ```bash
   docker compose up -d
   ```
2. Открыть интерфейс Grafana [http://localhost:3000](http://localhost:3000)

3. Посмотреть текущий коэффициент ошибок (Error Rate) и Burn Rate. Дать приложению поработать 10 минут.

4. Исправить проблему с ошибками в файле main.go

5. Пересобрать и перезапустить сервис

```shell
docker compose up -d --build app
```

6. Спустя 10 минут посмотреть на графики.
