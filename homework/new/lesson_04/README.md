# Домашнее задание: Построение дашборда для 2-х сервисов

## Цель

Понять, как строить дашборды в Grafana и как их анализировать при инцидентах.

## Контекст

На уроке ранее вы познакомились с небольшой системой, построенной на 2-х микросервисах: `driver-location-service` и `track-analyzer-service`, для которой уже построены некоторые дашборды.

> **Важно:** Пример дашборда с решением вы найдете в поднятом инстансе Grafana, но не смотрите в него, пока не попробуете решить задачу самостоятельно. Наибольшую пользу от обучения вы получите именно путем собственных проб и ошибок.

---

## Задача

Проект находится в репозитории: [observability-course/lesson_05/project](https://github.com/make-it-git/observability-course/tree/main/homework/new/lesson_04/project).

Ваша задача — построить дашборд, по которому можно анализировать работу обоих сервисов в разрезе:

* **RPS для каждого статуса для каждого API endpoint**
* *Пример:* RPS 200-х ответов сервиса для каждой ручки каждого сервиса.
* *Пример:* RPS 5xx ответов сервиса для каждой ручки каждого сервиса.


* **Latency ответов в разрезе самых «тяжелых» ответов**
* Это значит, что в случае большого количества сервисов и API endpoints мы хотим видеть все медленные ручки сервисов.


* **Процент успешных запросов по каждой ручке сервиса**

### Фильтрация и переменные

Дашборд должен поддерживать фильтрацию по сервису:

* Используйте [label values](https://grafana.com/docs/grafana/latest/datasources/prometheus/template-variables/) для получения списка сервисов динамически и настройте variables.

---

## Анализ и проверка

Далее по построенным дашбордам нужно выполнить анализ:

1. Запустите сервисы через `docker compose`.
2. Создайте нагрузку через команду `k6 run k6/load-test.js`.
3. Используйте построенный дашборд для ответа на вопросы:
* Какие ручки каких сервисов дают ошибки?
* Какие ручки каких сервисов тормозят?



### Добавление задержек (симуляция инцидента)

Для того чтобы добавить «тормоза» (когда дашборд уже построен и нагрузочный скрипт сгенерировал достаточно метрик), выполните:

```bash
curl -X PUT localhost:8081/api/v1/features/add-point-delay-value-start -d '{"value": 500}' -v
curl -X PUT localhost:8081/api/v1/features/add-point-delay-value-end -d   '{"value": 700}' -v

```

Это создаст случайные тормоза от 500 до 700 мс. А в каком сервисе и для какой ручки — это необходимо понять по построенным дашбордам.

Попробуйте также после анализа увеличить значения, чтобы получить ошибки. Например, поставить «тормоза» от 500 до 1000 мс.
